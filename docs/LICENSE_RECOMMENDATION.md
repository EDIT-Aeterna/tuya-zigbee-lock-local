# Licensing / provenance guidance

The upstream project:

`nickieftekhari-dotcom/Door-Lock-TY0A01-with-TYZS3-to-Z2M-firmware`

currently has no explicit LICENSE file in the repository.

## Current TZLL policy

- Do not assume that the absence of a LICENSE creates an open-source license grant.
- Do not add a blanket MIT/GPL/Apache license over upstream-derived code without explicit rights/permission supporting that action.
- Preserve upstream attribution and Git history.
- Record provenance for substantial copied/derived material.
- Keep release notes and public descriptions from implying that TZLL has resolved upstream licensing when it has not.

See [UPSTREAM_AND_PROVENANCE.md](UPSTREAM_AND_PROVENANCE.md) for the technical relationship.

## Possible future paths

After rights are clarified, maintainers may consider:

1. obtaining explicit permission/license terms from the upstream author;
2. documenting separately-authored TZLL components at file/subtree level where appropriate;
3. performing a deliberately independent reimplementation of selected components if a clean licensing boundary is needed.

A future license decision should distinguish original TZLL work from upstream-derived work rather than retroactively treating the entire history as newly licensed.

This file is project-governance guidance, not legal advice.
