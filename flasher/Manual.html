Kagel Lock Flasher

Load Kagel firmware onto a lock module over SWD in about five seconds. Wire it once, run the app, and each board goes from bare to ready in a single step.

Target · EFR32MG13 (TYZS3) Probe · Raspberry Pi Debug Probe Per board · ~4–5 s

What's in this folder

FileWhat it is
KagelLockFlasher.exeThe app — double-click this to open. No Python needed to run it.
kagel_flasher.pyThe source (only if you want to edit or rebuild).
kagel-lock.hexThe firmware that gets written. The app shows its size and sha — confirm they match the release you intend to ship.

One-time setup · per PC

Only needed the first time on a given flashing computer. Install Python 3, then run these two commands:

:: install pyOCD (the flashing engine)
pip install pyocd

:: add the chip support pack (downloads once)
pyocd pack install efr32mg13p732f512gm48

Tip — plug the Debug Probe into the PC before launching. In the app's log line you should see it find pyocd and the target.

Wiring · probe to board

Three signal wires plus power. The app shows a live Debug Probe: connected indicator once wired and plugged in. Colours below match the Debug Probe's standard DEBUG cable.

FromWireTo (module)
Probe SWCLKorangepin 12 — SWCLK
Probe SWDIOyellowpin 11 — SWDIO
Probe GNDblackpin 9 — GND
Bench +3.3 Vredpin 8 — 3V3 (via carrier)

Ground must be shared. The probe's DEBUG port carries no power and no reset — the board is powered by the bench supply, and the probe ground, supply ground, and module pin 9 all connect together. Keep the jig leads short.

Flashing a board

Manual — one at a time

  1. Double-click KagelLockFlasher.exe.
  2. Seat a board on the jig.
  3. Press ⚡ FLASH.
  4. Wait for the green DONE ✓, then remove the board.

Auto — assembly line

  1. Tick Auto-flash.
  2. Seat a board — it flashes on its own.
  3. Green means done; lift the board off.
  4. Seat the next; the counter climbs.

After every flash the tool verifies the board booted Kagel firmware — a bad contact can't pass as a success.

If something goes wrong

SymptomFix
Red FAILED immediatelyNo board detected — check the three signal wires and that the bench 3.3 V is on. Grounds tied together.
Stays on FLASHING… then failsPoor contact mid-write. Reseat the board; keep leads short. If it repeats, drop the SWD clock (edit SWD_FREQ to 4000000).
“VERIFY FAILED — still stock”The write didn't take. Reseat and retry; the board is never left half-flashed.
App won't openRun the one-time setup (Python + pip install pyocd + the pack).
Probe not foundReplug the Debug Probe; confirm pyocd list shows it.
